Great question — the short answer is: don't give an agent your real shell; give it sandboxed tools scoped to specific folders. There are three common patterns:
1. Dedicated filesystem tools (best default)
Instead of a shell, expose narrow tools like list_dir, read_file, write_file, search. This is what most production agents do because it's auditable and hard to abuse.
•  MCP Filesystem Server (@modelcontextprotocol/server-filesystem) — the official Model Context Protocol server. You pass allowed directories at startup (or via the MCP "roots" protocol), and all operations are restricted to those paths. Works with Claude Desktop, and any MCP client (npm).
•  LangChain / LlamaIndex have built-in file toolkit agents (FileManagementToolkit in LangChain Community) you can wrap around a root folder.
2. Sandboxed shell (when the agent really needs commands)
If the agent must run shell commands (cd, build, git, etc.), run them inside isolation, never directly on the host:
•  Docker / Docker Sandboxes — mount only the project folder as a volume; Docker now positions "Sandboxes" explicitly as guardrails for autonomous agents running arbitrary commands (overview).
•  E2B — open-source firecracker-microVM sandboxes with an SDK; the agent runs shell commands inside the VM via runCmd, and you can copy files in/out. Popular with Mastra, CrewAI, etc. (Mastra docs).
•  Alternatives in the same space: Daytona, Cloudflare Sandbox, Microsandbox/Firecracker.
3. Local libraries for wiring it up yourself
•  Python: subprocess (with shell=False + arg lists, cwd= set to the allowed root, timeout=), or asyncio.create_subprocess_exec. For interactive shells: pexpect.
•  Node/TypeScript: execa or Google's zx (never raw child_process.exec with model-generated strings — command injection).
•  Docker SDKs: docker-py / dockerode to spawn ephemeral containers per session.
Safety checklist
 1.  Whitelist paths — resolve paths and reject anything escaping the allowed root (beware ../, symlinks).
 2.  Read-only by default; require explicit approval for writes/deletes.
 3.  Timeouts + output size limits on every command.
 4.  No secrets in the sandbox env (no API keys, SSH keys).
 5.  For API-based agents (OpenAI/Anthropic function calling), same rules apply — the tool definition is your security boundary, not the prompt.
TL;DR: Use the MCP filesystem server (or a custom tool wrapper) for folder navigation, and E2B/Docker when actual shell execution is needed.
